# SBA-IMS Production Deployment Guide (Ubuntu Linux)

This guide documents the procedures for installing, configuring, securing, and deploying the SuperBee Aeronautics Inventory Management System (SBA-IMS) v1.4 on a fresh Ubuntu 22.04 or 24.04 LTS server.

---

## 1. System Requirements

* **Operating System**: Ubuntu 22.04 LTS or Ubuntu 24.04 LTS
* **Node.js**: v22.14.0 (LTS)
* **Database**: MySQL 8.0+
* **Web Server**: Nginx (configured as reverse proxy and static asset server)
* **Process Manager**: PM2 (for keeping the Node.js API server running)
* **SSL/TLS**: Let's Encrypt / Certbot (port 443 SSL mandatory for HttpOnly cookies)

---

## 2. Server Prerequisites Installation

Execute the following commands on your Ubuntu server to update packages and install standard requirements:

```bash
# Update packages
sudo apt update && sudo apt upgrade -y

# Install git, curl, build-essential, and Nginx
sudo apt install -y git curl build-essential nginx mysql-client mysql-server

# Verify MySQL status
sudo systemctl status mysql
```

---

## 3. Node.js LTS Installation (via NodeSource)

SBA-IMS requires Node.js v22. You can install it using NodeSource:

```bash
# Download and install NodeSource GPG key and repository
sudo apt-get update
sudo apt-get install -y ca-certificates curl gnupg
sudo mkdir -p /etc/apt/keyrings
curl -fsSL https://deb.nodesource.com/gpgkey/nodesource-repo.gpg.key | sudo gpg --dearmor -o /etc/apt/keyrings/nodesource.gpg
echo "deb [signed-by=/etc/apt/keyrings/nodesource.gpg] https://deb.nodesource.com/node_22.x nodistro main" | sudo tee /etc/apt/sources.list.d/nodesource.list

# Install Node.js
sudo apt-get update
sudo apt-get install nodejs -y

# Verify versions
node -v  # Should be v22.x.x
npm -v
```

## 5. Production Database Configuration

### Step 5.1: Database Credentials Security (Least Privilege)
We strongly recommend setting up a dedicated user `sba_app` for application queries rather than using database root access:

```sql
-- Connect to MySQL: mysql -u root -p
CREATE DATABASE superbee_inventory;

-- Create least-privilege user
CREATE USER 'sba_app'@'localhost' IDENTIFIED BY 'your_strong_password_here';

-- Grant DML and DDL permissions
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, DROP, REFERENCES, INDEX, ALTER, CREATE TEMPORARY TABLES, LOCK TABLES, TRIGGER ON superbee_inventory.* TO 'sba_app'@'localhost';

FLUSH PRIVILEGES;
```

### Step 5.2: Configure Environment Variables
Modify the production environment configurations inside `backend/.env`:

```bash
nano backend/.env
```

Ensure the database connection variables match the credentials created above, and verify production security properties:
```env
NODE_ENV=production
PORT=5000
JWT_SECRET=your_long_secure_random_hex_string
SESSION_SECRET=your_long_secure_random_session_secret
DB_HOST=localhost
DB_PORT=3306
DB_USER=sba_app
DB_PASSWORD=your_strong_password_here
DB_NAME=superbee_inventory
CORS_ORIGIN=https://superbee.yourdomain.com
COOKIE_DOMAIN=yourdomain.com
HTTPS_ONLY=true
```

## 6. PM2 Process Manager & Service Startup

PM2 manages the Node.js process lifecycle, keeping it running in the background and restarting it on server reboots.

```bash
# Install PM2 globally
sudo npm install pm2 -g

# Start the backend API service under PM2
cd backend
NODE_ENV=production pm2 start server.js --name "sba-backend"

# Save list of PM2 processes to survive reboots
pm2 save

# Setup PM2 startup script
pm2 startup
```
Copy and execute the output command generated by `pm2 startup` to configure the systemd service.

## 7. Nginx Web Server & Reverse Proxy Configuration

Nginx will serve the static compiled React assets directly and proxy `/api` requests to the Node.js API server.

### Step 7.1: Setup Nginx Site Configuration
Create a virtual host configuration:

```bash
sudo nano /etc/nginx/sites-available/sba-ims
```

Add the following configuration (replace `superbee.yourdomain.com` with your domain):

```nginx
server {
    listen 80;
    server_name superbee.yourdomain.com;

    # Redirect all HTTP traffic to HTTPS (Certbot will overwrite this, but good practice)
    location / {
        return 301 https://$host$request_uri;
    }
}

server {
    listen 443 ssl http2;
    server_name superbee.yourdomain.com;

    # SSL Certificates (managed by Certbot)
    # ssl_certificate /etc/letsencrypt/live/superbee.yourdomain.com/fullchain.pem;
    # ssl_certificate_key /etc/letsencrypt/live/superbee.yourdomain.com/privkey.pem;

    # Security Headers
    add_header Content-Security-Policy "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: https:; connect-src 'self' https://superbee.yourdomain.com; frame-src 'none'; object-src 'none'; base-uri 'self';" always;
    add_header X-Frame-Options "DENY" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;

    # Static Frontend Assets
    location / {
        root /home/ubuntu/superbee_inventory/dist;
        index index.html;
        try_files $uri $uri/ /index.html;
    }

    # Reverse Proxy to Node.js Backend API
    location /api/ {
        proxy_pass http://127.0.0.1:5000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

### Step 7.2: Enable Site and Restart Nginx
```bash
# Link configuration
sudo ln -s /etc/nginx/sites-available/sba-ims /etc/nginx/sites-enabled/

# Remove default site if present
sudo rm -f /etc/nginx/sites-enabled/default

# Test Nginx syntax
sudo nginx -t

# Reload Nginx
sudo systemctl reload nginx
```

## 8. SSL Certificate Setup (Let's Encrypt / Certbot)

HTTPS is strictly required because authentication tokens are sent using `HttpOnly; Secure; SameSite=Strict` cookies.

```bash
# Install Certbot and the Nginx plugin
sudo apt install -y certbot python3-certbot-nginx

# Obtain SSL Certificate
sudo certbot --nginx -d superbee.yourdomain.com

# Verify automated certificate renewal
sudo systemctl status certbot.timer
```

## 9. Troubleshooting & Operations

### 9.1 Database SSL Errors in Local / Non-TLS Setup
If you are testing the production bundle locally without TLS configured on your MySQL database, the connection might fail with:
`self-signed certificate in certificate chain` or `rejectUnauthorized`.
To run in production mode on servers without TLS databases, you must set the environment variable:
`DB_CA_CERT=` (empty) and configure rejects appropriately inside `backend/config/database.js`.

### 9.2 Process Monitoring
```bash
# Check PM2 statuses
pm2 status

# View live API logs
pm2 logs sba-backend

# Restart service
pm2 restart sba-backend
```
